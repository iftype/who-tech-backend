# 0003 구조 변경의 안전망: 계약·스크린샷·운영 지문

- 상태: 적용 (2026-10-19, #183 이후 모든 구조 PR)

## 배경

구조 개선의 첫 원칙은 "운영 기능 불변"이었다. 폴더를 옮기고 파일을 나누는 PR이 열 개 넘게 이어지는데, 사람이 화면을 눌러 보는 것만으로는 미세한 변화(정렬, 빈 값 처리, 클래스 하나)를 놓친다. 기존 단위 테스트는 구현에 붙어 있어 구조를 바꾸면 같이 바뀌므로 안전망이 되지 못한다.

## 결정

구현이 아니라 **바깥에서 보이는 결과**를 고정하는 장치를 먼저 깔고 구조를 바꾼다.

1. **API 계약 테스트**: 고정 시드 데이터로 공개·어드민 API 응답 107개를 스냅샷으로 고정 (`api-contract.int.test.ts`)
2. **스크린샷 비교**: 어드민 탭 9장을 Linux CI에서 찍은 기준 이미지와 픽셀 비교. 시간대·로케일·커밋 표시를 고정해 흔들림을 없앴다
3. **동작 고정 테스트**: 큰 탭을 나누기 전에 그 탭의 흐름(칸 편집·모달·SSE 로그·폴링·일괄 변경)을 테스트로 쓰고, 옛 코드와 새 코드에서 똑같이 통과하는 것을 확인한 뒤 바꾼다
4. **운영 지문**: 배포 전후로 운영 API 27개 응답 해시를 비교한다 (`scripts/api-fingerprint.mjs`). 다르면 즉시 되돌린다
5. 부품으로 옮긴 클래스는 원래 문자열과 같은 집합인지 단위 테스트로 고정한다 (화면 변화 0의 근거)

## 결과

- 모든 구조 PR에서 스크린샷 0픽셀 차이, 계약 스냅샷 동일, 운영 지문 동일
- 동작 고정 테스트가 기존 버그를 하나 잡았다: 멤버 표 정렬 머리 칸이 다시 그려질 때마다 새로 붙어 클릭이 가끔 사라졌다(부하에서 6번 중 3번 실패). 화면 변화 없이 고쳤다
- 검증하며 드러난 다른 기존 버그(이전 GitHub ID 이중 쓰기, JSON 형식 오류로 공개 검색 500 등)는 구조 PR에서 고치지 않고 기록한 뒤 별도 단계에서 다뤘다

## 비용

- 스크린샷 기준 이미지는 Linux에서만 만든다(로컬 macOS와 글꼴 렌더링이 달라서). 기준을 바꿀 때는 CI의 `update_snapshots` 입력으로 다시 찍는다
- 시드·스냅샷은 공개 저장소에 들어가므로 개인 정보는 익명화하고 소유자 데이터만 남겼다
